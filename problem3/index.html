01 · The method

Don't refactor on sight. Triage first.

Messy code invites you to rewrite everything at once — that is how regressions are born. Work in five deliberate passes.

Read

Skim the whole file once without touching it. Write down what it is supposed to do, in one sentence.

Pin behaviour

Run it. Add a quick test or snapshot around the current output so you'll notice if you change it by accident.

Classify

List every smell and tag it L1–L5 using the questions below. Count them — that's your scorecard.

Fix in layers

L1 → L5, one commit per layer. Cheap, safe changes first shrink the noise so the deep problems become visible.

Verify

Tests green, Profiler shows fewer renders, lint is clean. Then explain each change in the PR in one line.

02 · Identify & classify

Five questions sort any smell

Ask them in order — the first “yes” is the level. It works because each question is about a bigger blast radius than the last.

L2
Does it give a wrong result, crash, or warn in the console?Yes → Correctness bug. Undefined variables, inverted conditions, bad keys, mutated state.
L3
Is the output right, but it re-renders or recomputes too much?Yes → Render performance. Wrong memo deps, unstable props, repeated work.
L4
Is the same truth stored twice, or synced with an effect?Yes → State & effects. Derived state, races, stale closures, missing cleanup.
L5
Does the file do more than one job, or is it impossible to test?Yes → Architecture. God components, fetching + logic + UI fused together.
L1
None of the above, but it's hard to read?→ Hygiene. Naming, dead code, any, magic numbers, stray logs.

Let the tools find them for you

ESLint + react-hooksL1–L4exhaustive-deps, rules-of-hooks, react/jsx-key, no-unused-vars catch a third of all smells in seconds.
TypeScript strictL1–L2strict: true + noImplicitAny surface undefined names, missing fields and lying types.
React StrictModeL4Double-invokes effects in dev, so missing cleanups and impure renders show up immediately.
DevTools ProfilerL3“Highlight updates” and the flame chart show what re-renders and why.
Line count & importsL5300+ lines, 15+ imports, or both fetch and <svg> in one file is an architecture smell.

04 · Prioritize

Impact vs effort: pick quick wins first

Easy-to-hard is the order of difficulty. When time is short, plot each smell and take the top-left quadrant before anything else. Select a dot for details.

Select a dotEach smell is coloured by level.
↖ Quick winsLow effort, high impact. Do today.
↗ Big betsHigh impact, real effort. Plan them, ticket them.
↙ Fill-insCheap and minor. Batch with other work.
↘ Think twiceExpensive, little payoff. Usually skip.
